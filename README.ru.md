# Verdict

ИИ-суд над маркетинговыми проектами. [English version](README.md) · спецификация — в [SPEC.md](SPEC.md).

## Запуск

```bash
npm install
npm run dev
```

Откройте http://localhost:3000 → «Настройки» и подключите хотя бы одного провайдера.
Чтобы попробовать без трат на API, добавьте провайдера «Демо»: он разыгрывает правдоподобное заседание без моделей.

## Провайдеры

| Способ | Что нужно |
|---|---|
| **Anthropic / OpenAI / Gemini API** | API-ключ из консоли провайдера |
| **OpenRouter** | Кнопка «Войти через OpenRouter»: вход в браузере (OAuth PKCE), ключ создаётся и сохраняется сам. Или вставьте готовый ключ |
| **Ollama** | [ollama.com](https://ollama.com), `ollama pull llama3.2`, `ollama serve`. Ключ не нужен, адрес по умолчанию `http://localhost:11434/v1` |
| **Claude Code** (подписка Claude) | `npm i -g @anthropic-ai/claude-code`, затем `claude auth login` |
| **Codex CLI** (подписка ChatGPT) | `npm i -g @openai/codex`, затем `codex login` |
| **Gemini CLI** (аккаунт Google) | `npm i -g @google/gemini-cli`, запустите `gemini` и выберите «Login with Google» |

CLI-мосты вызывают установленную программу как отдельный процесс: без инструментов, без доступа к файлам
проекта (рабочая папка — `data/cli-sandbox`), без сохранения сессий. Если программы нет в PATH, укажите путь
в поле «Дополнительно → Путь к программе». Картинки через CLI понимает только Codex; остальным передаётся
текстовое описание. **Использование подписок через сторонние приложения регулируется условиями
провайдера — проверьте их самостоятельно.**

## Материалы

На главной перетащите файлы на скамью подсудимых или вставьте текст. Поддерживаются:
картинки (PNG, JPEG, WebP, GIF), видео (MP4, MOV, WebM), PDF, DOCX и текстовые файлы.

- **Видео** лучше всего разбирает Gemini (нативно). Без Gemini нужен **ffmpeg** в PATH: из ролика
  вынимаются ключевые кадры, а речь расшифровывает Whisper, если подключён провайдер OpenAI.
- **Картинки** модели со зрением получают целиком; для остальных пишется подробное описание.
- Перед заседанием всё это видно на экране «Материалы дела» и редактируется.

Файлы дела хранятся в `./data/uploads/` и удаляются вместе с делом.

## После вердикта

- **Апелляция** — выберите аудиторию из предложенных или впишите свою: суд проведёт короткое слушание
  (2–3 заседания) и даст советы под неё. Апелляции видны у исходного дела и в архиве.
- **Новая версия** — доработали материал по советам суда? «Подать новую версию» в отчёте: тот же состав суда
  получит свой прошлый вердикт, секретарь сравнит версии и отметит, какие советы выполнены, а судья по каждому
  прошлому совету скажет, остаётся ли он в силе, — и если суд передумал, объяснит почему. Если загрузить новую
  версию с главной, суд сам заметит похожее дело в архиве и предложит повторное рассмотрение.
- **Экспорт** — Markdown-файл или печатная версия («Сохранить как PDF» в диалоге печати;
  `/cases/<id>/print?preview=1` — просмотр без диалога).
- **Фактический результат** — CTR, конверсия, продажи и заметка: в архиве прогноз видно рядом с реальностью.

## Сколько спорит суд

После каждого заседания секретарь решает, прозвучали ли новые доводы. Слушания закрываются, когда новых доводов нет,
или когда оценки сошлись (стандартное отклонение ниже порога, по умолчанию 6) и новых доводов тоже нет. Если оценки
сошлись, но спор принёс новое, суд проводит ещё одно заседание; если оценки сошлись второй раз подряд — закрывается.
Минимум, максимум заседаний и порог меняются в настройках.

Решение об остановке принимает код, причём до того, как секретарь напишет обоснование: секретарю сообщают исход
по регламенту (или оба возможных исхода, если всё решает новизна доводов), поэтому его текст не расходится с решением.
Секретарь также ведёт список установленных фактов, в которых стороны уже сошлись: участники видят его и не пересказывают.

## Две оценки, расчёты и срочность советов

- Участники ставят две оценки: **вероятность успеха** (с рыночными рисками, которые документом не снять)
  и **качество плана** (насколько он продуман и согласован). Вердикт показывает обе, при повторном
  рассмотрении — динамику каждой.
- Расчёты участники записывают выражениями с допущениями, а считает их код (`src/lib/trial/calc.ts`):
  спор идёт о входных числах, а не об умножении.
- Судья помечает каждый совет: **блокирует запуск** или **по ходу** (блокирующих — не больше трёх).
  Так видно, когда пора остановиться и запускать.

## Токены и кэш

Правила суда и материалы дела одинаковы для всех выступающих, поэтому они вынесены в общий системный промпт,
а роль участника — в его сообщение. Провайдеры кэшируют это общее начало: Anthropic — по метке кэша, OpenAI,
Gemini и Claude Code — автоматически. В первом заседании на каждой модели один участник отвечает первым и
наполняет кэш, остальные читают из него. В отчёте видно, сколько входных токенов прочитано из кэша.

Промпты всех участников лежат в `prompts/` — их можно править без перезапуска (см. `prompts/README.md`).

Локальные данные (БД SQLite, ключ шифрования API-ключей) лежат в `./data` и не попадают в git.
Если удалить `data/secret.key`, сохранённые API-ключи станут нечитаемыми — их придётся ввести заново.
